Interface notes

The rules behind the redesign, written so they can be implemented as tokens and shared components rather than page-by-page fixes.

Principles

One title per page
The top bar carries breadcrumbs only. The H1 lives in the content. Never repeat the page name.
Group, don’t box
One container per task. Related numbers share a single strip split by hairlines, not four floating cards.
Color means state
No tinted icon tiles. Only warnings, failures and live/active states carry color. Everything else is ink and grey.
Tabs are the summary
If a status has a count, show it once — in the tab. Remove stat cards that repeat tab counts.
Counts from the server
Never “on this page”. Tab and nav counts are totals for the whole dataset.
Empty states explain
Say why it’s empty and link to the next action. “No data” alone is a bug.

Data issues spotted in the current build

• Revenue charts say “no paid orders” while 106 paid orders exist — the query requires paid and delivered. Label it as delivered revenue, or plot paid.
• Orders page deltas (↑193.8%, ↑198.0%) are identical to Analytics deltas on different base numbers — check they aren’t reused.
• Average order GH₵438 ≠ 41,534 ÷ 106 (≈ GH₵392). Confirm what the average is taken over.
• Status counts are page-scoped (“Pending 15 on this page”) while the dashboard says 78. Use server totals everywhere.
• Every user is counted as a Customer (29 of 29), so the role filter can’t isolate shoppers. Filter by primary role.
• Deleted accounts show as “Blocked”. Give them their own state and hide them from the default list.
